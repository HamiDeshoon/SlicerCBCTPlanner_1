# v3.3 Surgical Guide Insertion, Sleeve Ring Schema & Intaglio Body Spec

## Context & Scope
Three orthogonal additions to the F14 surgical guide path, ported in spirit (not code) from the external `SurgicalPlanner` extension. Everything operates on the existing `(Z, Y, X)` label mask + `IJK->RAS` affine pair already used by `adt/geometry.extract_isosurface_from_label`; no new runtime dependency, no mesh boolean library, and no invented clinical values:

1. **Mask-Space Path-of-Insertion Undercut Check (`CBCTPlannerLib/core/insertion.py`, `ImplantPlanner.py`, `Phase7Tools.py`, `CBCTPlanner.py`)**:
   - **CR-1 — Voxel-Exact Sweep, No Interpolation**: `compute_blocked_surface(mask_zyx, affine, axis_apical_ras, *, label_ids=None, center_ras=None, roi_mm=25.0, coronal_band_mm=None) -> UndercutReport`. The surface is `mask & ~erode6(mask)` computed with padded NumPy shifts; a surface voxel is blocked when any `mask[v - m*u]` for `m >= 1` is occupied, marched along the coronal draw direction (`-axis_apical_ras`) with integer Bresenham steps scaled to the dominant voxel axis. `worst_depth_mm = max(m) * step_mm`.
   - **CR-2 — ROI Crop, Auto-Stride & Apical Exclusion**: the crop is bounded by `roi_mm` around `center_ras` (or the mask bounds) and auto-strided when any axis exceeds `MAX_CROPPED_GRID_DIM = 128`, with the affine origin and spacing adjusted so reported depths stay in mm. Central-difference outward normals replace cardinal-face rounding; strictly apical faces (`dot(n, -u) < -0.55`) are excluded so flat bases, root apices and the inferior mandibular border do not report every coronal shadow above them as blocked. `coronal_band_mm` optionally restricts candidates to the coronal seating collar the guide actually contacts.
   - **CR-3 — Honest Verdict & Disclaimer**: `is_insertable = blocked_fraction <= max(0.02, 3 / surface_voxel_count)`; every report carries a one-voxel stair-step uncertainty warning and the fixed string `GEOMETRIC_DISCLAIMER` (`"geometric obstruction, not a clinical contraindication"`). Empty, single-voxel and band-empty masks return zeroed counts with `is_insertable=True` instead of raising.
   - **CR-4 — Axis Search**: `suggest_insertion_axis(..., seed_axis_ras, max_tilt_deg=20.0, n_candidates=13, center_ras, roi_mm)` scores a golden-angle tilt cone plus a 1-ring refinement within the cone, ranking by `(blocked_fraction, worst_depth_mm, tilt_from_seed)` so the least-tilted clear axis wins.
   - **CR-5 — One Shared Draw Axis**: the guide seats as a single rigid body, so the undercut verdict is a guide-level property. `GuideBuildReport` carries `seating_axis_ras` and `undercut_blocked_fraction` (persisted under `guide_build` in `surgical_guide_sleeves.json`). `PlacedImplant.undercut_blocked_fraction` / `insertion_axis_suggested_ras` remain informational per-implant annotations only.
   - **CR-6 — Step 6 UI, Not Step 7**: the guide controls live in Step 6, so results are reported in `step6HintLabel`. A `Check Draw Direction` button evaluates the shared axis (mean of placed implant axes when no explicit axis is supplied) with `coronal_band_mm = max(8.0, guide_thickness_mm + 6.0)`.

2. **Implant Library Schema v1.1 — Real Sleeve Rings (`Resources/generic_implant_library.json`, `ImplantPlanner.py`, `Phase7Tools.py`)**:
   - **CR-7 — Optional Keys, No Invented Numbers**: `schema_version` becomes `"1.1"`; entries may carry `ring_outer_diameter_mm`, `ring_inner_diameter_mm`, `ring_height_mm`, `sleeve_offset_mm`, `sleeved`. The twelve bundled generic entries are left **numerically unchanged** (all ring fields `None`, `sleeved=True`); v1.0 files without the keys still load.
   - **CR-8 — Pocket vs Integral Tube**: `SurgicalGuideGenerator.resolve_sleeve_dimensions(preset, implant)` returns `metal_ring` when a complete positive ring triple exists (printed **pocket** = `ring_od + 2*clearance`, pocket height = `ring_height_mm`, drill bore = `ring_inner_diameter_mm`, offset from `sleeve_offset_mm`), otherwise the unchanged `integral_tube` formula (bore = `diameter_mm + 2*clearance`, wall from the printer preset).
   - **CR-9 — Consistency Warnings Only**: `GuideSleeveSpec` gains defaulted `pocket_diameter_mm`, `pocket_height_mm`, `sleeve_kind`, plus warnings for `ring_od <= platform_diameter_mm`, `ring_id >= ring_od`, and a preset sleeve height exceeding the ring height. No new clinical claim is made from these numbers.

3. **Anatomy-Conforming Intaglio Guide Body (`Phase7Tools.SurgicalGuideGenerator`, `CBCTPlanner.py`)**:
   - **CR-10 — EDT Shell, Not Mesh Booleans**: `generate_surgical_guide(..., volume=None, mask_zyx=None, affine=None, seating_axis_ras=None, smooth=True, body_mode="auto"|"analytic"|"intaglio", arch_band_mm=10.0)`. Supporting voxels are cropped by arch distance (`cKDTree` to the arch curve), projected into a solid along the seating axis so the shell cannot wrap under flat slabs or the mandibular base, then banded by `scipy.ndimage.distance_transform_edt`: `tissue_offset_mm <= d <= tissue_offset_mm + guide_thickness_mm`. A sub-voxel `tissue_offset_mm` is clamped to half a voxel and reported as a quantization warning.
   - **CR-11 — Fused Sleeve Collars, Open Channels**: solid outer collar cylinders are voxel-unioned **before** the pocket/bore columns are subtracted, so collars above the crest stay connected to the body instead of floating; a core-emptiness probe decides `sleeve_channels_open`.
   - **CR-12 — Single-Part Topology**: `scipy.ndimage.label` drops components below `50 mm^3`; `extract_isosurface_from_label` triangulates; optional pure-NumPy Laplacian smoothing (`_smooth_mesh_vertices`) never changes topology. `GuideBuildReport(body_mode, is_edge_manifold, volume_mm3, island_count, sleeve_channels_open, seating_axis_ras, undercut_blocked_fraction, warnings)` is written as `"guide_build"`, and always includes `"base derived from segmentation; verify fit"`.
   - **CR-13 — Analytic Fallback Stays Green**: `body_mode="analytic"`, or a missing/empty mask, returns the original arch-tube + hollow-sleeve meshes with a recorded warning, so the existing mask-less F14 integration test is unchanged. Surface extraction works without `scikit-image`/`vtk` through the pure-NumPy voxel-quad fallback, which is what CI exercises (`ruff`, `numpy`, `scipy` only).

## Out of Scope
- Tooth STL geometry (licence/provenance unresolved), `fpdf` report generation, DICOM inspector/launcher, `VirtualProsth` placement, registration, and `pyacvd` remeshing from the source extension.
- Inventing ring dimensions, drill-kit data, or manufacturer-specific values for the generic library.
- Mesh-space (post-boolean) seatability cross-checks of the exported STL, and a printability lint (min wall, resin traps, build orientation); both remain future work.
- Any VERSION bump; `Resources/VERSION` stays `3.3.0` for this change.
